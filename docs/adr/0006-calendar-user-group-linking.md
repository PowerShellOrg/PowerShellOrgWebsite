# Calendar entries link back to their user group by matching the Meetup URL host at render time, not an explicit stored field

Calendar entries (`content/calendar/meetup-*.md`) are generated by
`.github/scripts/sync-meetup-events.mjs` from each user group's
`links[].url` on `meetup.com`; manual entries like
`ohio-powershell-user-group.md` also happen to carry a `meetup.com`
`externalUrl`. To show a group's logo/name badge on the calendar page and
link it back to `/user-groups/<slug>/`, the template
(`themes/powershell-community/layouts/_default/calendar.html`) matches each
entry's `externalUrl` host against every user group's `links[].url` host at
render time, rather than the sync script stamping a `userGroup: <slug>`
field into generated frontmatter.

## Considered options

- **Explicit `userGroup` field, written by the sync script** — rejected (for
  now). More "obviously correct" in the abstract, but the script currently
  discards the per-group URL once it flattens all groups' Meetup slugs into
  one set (`groups()` in `sync-meetup-events.mjs`), so this would mean
  threading that mapping through, resyncing/backfilling the 13 existing
  generated entries, and still leaving manual entries unmatched unless an
  author remembers to set the field by hand.
- **Runtime match on Meetup URL host** — chosen. The join key (the Meetup
  group slug embedded in both the calendar entry's `externalUrl` and the
  user group's `links[].url`) is already 100% reliable across every existing
  entry, synced or manual, with no script change and no backfill. It also
  means Ohio's hand-authored entry matches for free, since its
  `externalUrl` happens to be a `meetup.com` link too.

## Consequences

- Linking is **implicitly scoped to Meetup-sourced events.** A future
  non-Meetup user-group event (e.g. Eventbrite) will render with no group
  badge unless this matching logic is extended to other hosts, or unless we
  revisit this decision in favor of an explicit field.
- The match is **deliberately on URL host, not on a link's declared `icon` or
  `name`.** A user group that mislabels its Meetup link's icon still matches
  correctly, because the template never looks at it.
- The calendar template now has to enumerate `/user-groups/` pages per
  rendered event to find a match. This is a cheap, build-time cost (list
  sizes are small), not a runtime one — Hugo is a static site generator.
